# Eli's Lab Framework (ELF): Протокол Base-Delta для Agile R&D

Интегрированный стандарт логирования данных аппаратно-программного обеспечения и экспериментов (Протокол), разработанный для поддержки быстрых циклов обратной связи (Agile) на этапах разработки устройств и валидации результатов R&D. Гарантирует полную прослеживаемость данных, минимизируя утомление исследователя от документирования.

## Основная философия

* **Единственный источник истины:** Проектирование аппаратного обеспечения, аналитический код и необработанные данные органически связаны в пределах одного проекта.
* **Base-Delta логирование:** Не каждая переменная записывается. Определяется Исходное состояние (Base), и только изменённые переменные (Deltas) записываются в упрощённом виде, чтобы предотвратить задержки исследований.
* **Систематическое принуждение:** Обходит ограничения на длину имён файлов (ограничение Windows в 260 символов) и гарантирует воспроизводимость через код.
* **AI Governance:** Обеспечивает непрерывность работы AI-агентов через лог передачи данных `0_Meta/AI_Sync.md` и устанавливает единый стандарт логирования для людей и AI через `0_Meta/LogConvention.md`.

## Спецификация конвейера логирования данных

### 1. Соглашение об именовании файлов (Session-Trial Naming)

* Указание экспериментальных условий или информации о переменных в именах файлов **строго запрещено**.
* **Формат:** `[SessionID]_[TrialID].[extension]` (например, `S001_t1.csv`, `S001_t2.bin`)

### 2. Base-Delta логирование (гибридное логирование)

* **Лог выполнения (`5_Exp/53_Analysis/Logs/S###_log.md`):**
  * Повествовательный markdown-файл, который записывает циклы немедленной гипотеза-тест-урок в текстовом виде.
  * Пишется для каждого испытания (`t1`, `t2`...) в стиле потока сознания, записывая только **намеренно изменённые переменные (Delta)** и наблюдаемые результаты.
  * Формат и подробные правила: см. `0_Meta/LogConvention.md`.

### 3. Правила документов планирования

* Дорожные карты исследований, композиции рисунков, экспериментальные стратегии и т.д. управляются отдельно в `1_Concept/13_Planning/`.
* **Формат:** `P###_title.md` (например, `P001_wavelength_optimization.md`)
* При ссылке на Planning из лога: `→ see 1_Concept/13_Planning/P###_xxx.md`

### 4. Спецификация анализа постобработки (Cell Mode Scripting)

* Аналитический код должен находиться в `5_Exp/53_Analysis/Scripts/` или `5_Exp/51_Sim/Scripts/` и не должен смешиваться внутри папок данных.
* Используются чистые файлы `.m` вместо `.mlx` для предотвращения привязки к поставщику.
* Код выполняется по разделам, используя `%%` (Cell Mode), и полученные идеи отражаются в логе выполнения.
* Выходы анализа (рисунки, файлы mat) сохраняются в `5_Exp/54_Viz/` или `5_Exp/52_Empirical/Processed/S###/` в папках каждого сеанса.

### 5. Правила перекрёстных ссылок

Форматы перекрёстных ссылок унифицированы для обеспечения прослеживаемости между документами проекта.

| From → To | Format |
|-----------|--------|
| Logs → Planning | `→ see 1_Concept/13_Planning/P###_xxx.md` |
| Logs → Sim Data | `→ see 5_Exp/51_Sim/Data/S###/` |
| Logs → Script | `→ see 5_Exp/53_Analysis/Scripts/S###_analysis.m` |
| Planning → Logs | `← tracked in 5_Exp/53_Analysis/Logs/S###_log.md` |

## AI Governance

Когда AI-агенты (Claude, Gemini и т.д.) участвуют в проекте, применяются следующие правила:

1. **Получение контекста:** Перед началом работы прочитайте `0_Meta/AI_Sync.md`, чтобы подтвердить состояние предыдущей работы.
2. **Соответствие единому стандарту:** Следуйте правилам логирования в `0_Meta/LogConvention.md` так же, как человеческий исследователь.
3. **Запись передачи данных:** После завершения задачи запишите выполненные действия, созданные/изменённые файлы и Следующие шаги в `0_Meta/AI_Sync.md`. Пишите в обратном хронологическом порядке с самой свежей записью в начале.
4. **Разделение идей:** Гипотезы и идеи, созданные AI, сохраняются отдельно в `1_Concept/11_Ideas/`, а не в логах.
5. **Управление контекстом на основе PARA:** Используйте папку `9_Archive/` и `.claudeignore` для предотвращения загрязнения контекста AI. Для подробных правил см. `0_Meta/AI_PARA_Framework.md`.
6. **Правила коммуникации:** Поддерживайте объективный и сухой стиль письма. Нет аналогий или метафор. Доставляйте выводы ясно и прямо. Нет преувеличения или эмоциональных модификаторов. Для подробных правил см. раздел 3 файла `0_Meta/EliRule.md`.
7. **Переиспользование данных:** При создании любого графика/диаграммы сохраняйте исходный массив данных рядом как `.mat`/`.csv`. Для подробных правил см. раздел 2.6 файла `0_Meta/EliRule.md`.

## Быстрый старт

Чтобы создать новый проект со структурой ELF v2, запустите `0_Meta/ELF_generator.ps1`.

```
cd desired_parent_directory
D:\...\ELF\0_Meta\ELF_generator.ps1
```

Введите имя проекта, и структура папок 0–6, мета-документы, `.gitignore` и инициализация Git будут завершены автоматически.
