# إطار مختبر إيلي (ELF): بروتوكول Base-Delta للبحث والتطوير الرشيق

معيار تسجيل متكامل للأجهزة والبرامج وبيانات التجارب (Protocol) مصمم لدعم حلقات التغذية الراجعة السريعة (Agile) خلال مراحل تطوير الأجهزة والتحقق من صحة البحث والتطوير. يضمن قابلية تتبع البيانات الكاملة مع تقليل إرهاق توثيق الباحثين.

## الفلسفة الأساسية

* **مصدر واحد للحقيقة (Single Source of Truth):** تصميم الأجهزة والكود التحليلي والبيانات الخام مرتبطة عضويًا ضمن مشروع واحد.
* **تسجيل Base-Delta:** لا يتم تسجيل كل متغير. يتم التصريح عن Baseline، وتسجيل المتغيرات المتغيرة فقط (Deltas) بشكل خفيف لمنع تأخير البحث.
* **الإنفاذ المنتظم (Systematic Enforcement):** تجاوز قيود طول اسم الملف (حد Windows البالغ 260 حرفًا) وضمان الاستنساخية من خلال الكود.
* **حوكمة الذكاء الاصطناعي:** يضمن استمرارية عمل وكيل الذكاء الاصطناعي عبر سجل التسليم `0_Meta/AI_Sync.md`، وفرض معيار تسجيل موحد للبشر والذكاء الاصطناعي من خلال `0_Meta/LogConvention.md`.

## مواصفات خط أنابيب تسجيل البيانات

### 1. اتفاقية تسمية الملفات (تسمية الجلسة والتجربة)

* إدراج الشروط التجريبية أو معلومات المتغيرات في أسماء الملفات **محظور تماماً**.
* **الصيغة:** `[SessionID]_[TrialID].[extension]` (مثال: `S001_t1.csv`, `S001_t2.bin`)

### 2. تسجيل Base-Delta (تسجيل هجين)

* **سجل التشغيل (`5_Exp/53_Analysis/Logs/S###_log.md`):**
  * ملف markdown سردي يسجل دورات الفرضية-الاختبار-الدرس الفورية في نص.
  * مكتوب لكل تجربة (`t1`, `t2`...) بأسلوب تدفق الوعي، مسجلاً فقط **المتغيرات المتغيرة بقصد (Delta)** والنتائج المرصودة.
  * الصيغة والقواعس التفصيلية: راجع `0_Meta/LogConvention.md`.

### 3. قواعس مستند التخطيط

* يتم إدارة خرائط الطرق البحثية وتكوينات الأشكال والاستراتيجيات التجريبية وما إلى ذلك بشكل منفصل في `1_Concept/13_Planning/`.
* **الصيغة:** `P###_title.md` (مثال: `P001_wavelength_optimization.md`)
* عند الإشارة إلى التخطيط من سجل: `→ see 1_Concept/13_Planning/P###_xxx.md`

### 4. مواصفات تحليل المعالجة اللاحقة (كود وضع الخلية)

* يجب تموضع كود التحليل في `5_Exp/53_Analysis/Scripts/` أو `5_Exp/51_Sim/Scripts/` ويجب عدم مزجه داخل مجلدات البيانات.
* يتم استخدام ملفات `.m` النقية بدلاً من `.mlx` لمنع قفل البائع.
* يتم تنفيذ الكود قسماً تلو الآخر باستخدام `%%` (Cell Mode)، والرؤى المشتقة تنعكس في السجل المتواصل.
* يتم حفظ مخرجات التحليل (الأشكال وملفات mat) في `5_Exp/54_Viz/` أو `5_Exp/52_Empirical/Processed/S###/` ضمن مجلدات لكل جلسة.

### 5. قواعس المراجع الصليبية

يتم توحيد تنسيقات المراجع الصليبية لضمان قابلية التتبع بين مستندات المشروع.

| من → إلى | الصيغة |
|-----------|--------|
| سجلات → تخطيط | `→ see 1_Concept/13_Planning/P###_xxx.md` |
| سجلات → بيانات محاكاة | `→ see 5_Exp/51_Sim/Data/S###/` |
| سجلات → سكريبت | `→ see 5_Exp/53_Analysis/Scripts/S###_analysis.m` |
| تخطيط → سجلات | `← tracked in 5_Exp/53_Analysis/Logs/S###_log.md` |

## حوكمة الذكاء الاصطناعي

عند مشاركة وكلاء الذكاء الاصطناعي (Claude, Gemini, وما إلى ذلك) في المشروع، تنطبق القواعس التالية:

1. **الحصول على السياق:** قبل بدء العمل، اقرأ `0_Meta/AI_Sync.md` لتأكيد حالة العمل السابق.
2. **الامتثال للمعيار الموحد:** اتبع قواعس التسجيل في `0_Meta/LogConvention.md` بنفس الطريقة مثل الباحث البشري.
3. **تسجيل التسليم:** عند إكمال المهمة، سجل الإجراءات المنفذة والملفات المنشأة/المعدلة والخطوات التالية في `0_Meta/AI_Sync.md`. اكتب بترتيب زمني عكسي مع أحدث إدخال في الأعلى.
4. **فصل الأفكار:** يتم تخزين الفرضيات والأفكار التي ينشئها الذكاء الاصطناعي بشكل منفصل في `1_Concept/11_Ideas/`، وليس في السجلات.
5. **إدارة السياق بناءً على PARA:** استخدم مجلد `9_Archive/` و `.claudeignore` لمنع تلوث السياق للذكاء الاصطناعي. للحصول على القواعس التفصيلية، راجع `0_Meta/AI_PARA_Framework.md`.
6. **قواعس الاتصال:** الحفاظ على أسلوب الكتابة موضوعي وجاف. بدون تشبيهات أو استعارات. تقديم الاستنتاجات بوضوح وبشكل مباشر. بدون مبالغة أو معدلات عاطفية. للحصول على القواعس التفصيلية، راجع القسم 3 من `0_Meta/EliRule.md`.
7. **قابلية إعادة استخدام البيانات:** عند إنشاء أي Plot/Graph، احفظ مصفوفة البيانات الأصلية جنباً إلى جنب باسم `.mat`/`.csv`. للحصول على القواعس التفصيلية، راجع القسم 2.6 من `0_Meta/EliRule.md`.
